### Proposed packet order, conditional and non-overlapping

**During the current Codex run:** T1 profile coverage → T2 disclosure/test matrix → T3 environment/calendar truth matrix. These are source/audit questions that can be completed from exact selected repository records and **do not** need source mutation. T4 is worth one *new-evidence* shortlist only if a concrete local and item key can be grounded beyond PR #26's previous audit. T5–T9 are **already prepared or source-gated**: review deltas, do not burn connector effort re-reading unchanged input or producing duplicate draft trees.

**After user approves new canon but before UI activation:** select a small existing-place profile/enrichment batch under exact schemas; run full content validation in a repo checkout, then separately admit one read-only Codex map display. An authoring tool for names/profiles should edit **existing registries** with schema/lint checks; it must not create a new SQLite `locations` master or a gameplay UI editing Save.

**After accepted native gear/selected session and initial Current Area:** one G2 selected client acceptance pass; only then target T4 one G3 resource instance/action. T6 first real provider/NPC, T7 durable lineage narrative and T8 world/leyline/dungeon world generation each require their distinct authored/source and persistence gates. Do not package all together merely because their designs can advance now.
