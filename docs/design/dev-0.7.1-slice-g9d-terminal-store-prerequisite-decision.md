## Result

**G9D_SCHEMA_CONTRACT_REQUIRED; TERMINAL_IMPLEMENTATION_HELD.** G9A authorizes a terminal descendant and a durable lifecycle recovery in the same acceptance transaction. The current clean-epoch database is version 4 with no lifecycle store. Its sole descendant recovery validator requires `terminal=false` and exactly the four ordinary consumer plans; `publishDescendant` rejects terminal artifacts, while `completeDescendantConsumers` applies active-run projections. The generic campaign publication transaction extension can atomically write an additional row, but the account store cannot currently accept, resume, settle, or read back a terminal recovery. Calling the retained `archiveActiveRun` with `persistAccountProfile=false` and `deferSlotDeletion=true` is not a pure substitute: it still resolves slots through localStorage and its archive record clears slot membership. The selected `EpochApp` retirement control is deliberately held. Implementing retirement against those existing owners would split publication and settlement or consult the wrong storage authority.

This is the installed G9D prompt's explicit stop condition. No terminal code, browser data, schema upgrade, publication, payout, estate, slot deletion, deployment, or Game-version change is accepted by this decision.

## Smallest authorized implementation contract

1. Upgrade the isolated clean-epoch database from version 4 to 5 and add one `terminalLifecycleRecoveries` store keyed by `[accountId, campaignId, publicationId]`, with a unique `bySourcePublication` index on `[accountId, campaignId, sourcePublicationId]`. A lost caller discovers the one accepted terminal identity from its retained source. Upgrade only by adding the store; preserve all v4 accounts, attempts, recoveries, artifacts, controls, slots, and witnesses. Block a version-change race rather than reporting an empty account.
2. Retirement acceptance uses the generic campaign publisher with the lifecycle store in the *same* readwrite transaction. It validates exact account revision, completed first/descendant consumers, ready retained source artifact and publication, campaign head, observed source and destination address, and no pending Normal defeat. It writes a closed terminal descendant plus one pending lifecycle row; no account payout or address removal occurs in this phase. A different terminal identity or reason for the same source conflicts. A retry discovers and resumes the retained terminal publication rather than minting new IDs.
3. The lifecycle row retains version/status, account/campaign/character, source artifact/publication/raw snapshot, source and terminal slot addresses, expected head and account revision, archive reason `retired`, terminal artifact/publication/raw envelope, timestamp, exact planned consumer fingerprints, payout result and transaction identity, estate source-run identity, affected address IDs, and completed account revision. Validate the row against independent artifact, closed control, slot address, account and first/descendant recovery evidence before any duplicate or settlement decision. The fingerprint must cover reason, source/head/address, terminal artifact/publication, payout amount and source, estate source-run ID and affected addresses. Recompute derived payout and estate facts from retained inputs; agreement among mutable strings alone is insufficient.
4. Extract a **pure** retirement settlement projection from the accepted achievement, archive, Legacy payout and estate calculators. It must not call `listSaves`, `loadSave`, `publishSave`, `deleteSave`, `saveAccountProfile`, or localStorage. It receives the retained account/profile, terminal snapshot/publication, timestamp and exact address membership. It records authoritative retired history/reason, achievements, run payout metadata and at most one Legacy transaction, estate deposit, last-played and `retirement_settlement`/`estate` plus applicable publication receipts. Preserve active address membership until G9E closes it; preserve unrelated profile and immutable campaign history. Reject payout or estate calculation failure rather than silently recording success.
5. Settlement CASes the exact reserved account revision and changes the account and lifecycle row from pending to completed in one transaction. All ordinary account and campaign mutation paths must fence a pending lifecycle row, and a completed retry must verify its complete receipts and projection before returning the same result. Exact readback requires the closed campaign head and retained terminal artifact, the completed lifecycle row, the account revision/profile/receipts and unchanged immutable earlier artifacts and witness. A closed slot remains nonplayable; address closure and inheritance consumption belong to G9E.
6. After native owner proof, the selected App may wire its existing retirement control using the captured source, account revision and address. Show success only after completed exact readback. On restart or lost caller, discover the pending lifecycle by retained closed head/source and resume it. Ordinary/hardcore death remain outside this first G9D retirement package until an accepted gameplay caller supplies authoritative terminal state; do not infer death from UI status.
