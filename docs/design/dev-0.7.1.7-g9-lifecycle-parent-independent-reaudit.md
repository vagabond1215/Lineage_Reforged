## Repair boundary

F8 requires a request identity that distinguishes this selected action's submitted delete from another owner's same revision/generation deletion. The selected picker and Settings must retain an exact request only after their first actual submission and retry only that request after an uncertain post-commit outcome. An absent account before the selected action's first submission, or a changed request, must show stale/unavailable rather than success. The owner/adapter must validate durable tombstone binding; changing only a UI label is insufficient. Keep valid lost-acknowledgement retry, password/CAS fences, reset behavior, session invalidation, and historical G9E receipts. Add selected-App pre-submit absent, competing same-generation delete, changed request and exact lost-acknowledgement controls plus owner restart/two-owner/abort/readback regressions. Re-run the independent parent after repair; no repair suite can itself accept G9.
