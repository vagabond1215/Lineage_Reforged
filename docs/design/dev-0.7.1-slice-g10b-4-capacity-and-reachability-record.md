## Preimplementation gate and package boundary

Use a fresh localhost origin and unique synthetic epoch database. Create an ordinary Stonevein campaign through the production creator/first-campaign owner, then repeat the production nearby-exploration caller and descendant publication. Never force spawn selection, alter odds, insert a candidate or erase accepted history. A candidate from this sequence may be passed to the existing pure encounter builder **only for a projected-size measurement**; this does not admit combat or prove selected reachability. Measure JSON UTF-16 code units of every current account-owned row, snapshot and projected encounter; report browser `navigator.storage.estimate()` as an estimate, not a guarantee.

The bounded gate passes only if 24 accepted action/publication cycles retain exact readable head and history, at least one naturally selected candidate occurs, a disposable fault aborts one later publication without moving the prior head, and the measured browser estimate leaves a margin of **four times** the projected 24-encounter incremental bytes (each measured encounter payload plus an explicit 4 KiB receipt/command allowance) while remaining below half of the reported quota. The 4 KiB allowance is a provisional implementation ceiling to check against actual receipts later, not a fabricated persisted receipt. A missing quota estimate, no natural candidate, failed readback, unsized encounter, inadequate headroom, or unsafe abort is a bounded **capacity blocker** and stops production implementation. Historical Slice C's 5 MiB `localStorage` ceiling is a regression model, not the current epoch's product limit. This gate cannot accept long-running G10D capacity, eviction safety or backup/restore.
