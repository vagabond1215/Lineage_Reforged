## Exact bounded authoring and action route

1. **Static authoring slice.** Add one record to a new `world.encounter_action_contexts` collection, with schema and content-lint registration under the existing world content system. The first record's required facts are: stable context ID; action type `player.explore.nearby`; origin `settlement.stonevein`; local region `region.auric_marches`; origin hex `world_hex.auric_marches_ore_ridges`; selected edge `world_hex_edge.auric_marches_ore_ridges_auric_marches_caravan_marches`; `habitatTags: ["frontier_track"]`; and hazard source `region.auric_marches.simulationProfile.hazardPressure`. No template ID is forced into this record. The schema should reject unknown/ambiguous fields and duplicate identities. Semantic lint must prove settlement-to-hex anchor, edge endpoint and same-local-region coherence, parent chain, exact hazard existence/range, at least one intersecting eligible profile/template/member set, and uniqueness for the action/origin/edge tuple. Keep IDs and record shape extensible to other explicit origins/actions but implement exactly one record here. Do not edit `spawn_profiles.json` or `encounter_templates.json` merely to make the selected context pass.
2. **Reachable action and context-resolution slice, separately validated.** Add a bounded `player.explore.nearby` command to the game-engine action owner with a World-panel **Explore nearby environs** caller, available only from the exact current known settlement and an authored adjacent edge. Bind command/action identity, current settlement, region, source revision and campaign control. The accepted action produces its exact off-settlement context from the world record; the player's committed settlement remains Stonevein while the excursion area is separately identified until outcome. A no-candidate action returns a truthful no-encounter result. A candidate is only a pending fact for the separate campaign admission owner. Define and test time/resource effects in the action owner before exposing the control; do not copy the unrelated travel six-tick profile or generic shift effects. Reject absent, conflicting or stale mappings and all other origins/actions without a matching record. The resolver must validate local-to-macro ancestry and filter profile, template, movement/disposition, member habitat and hazard before deterministic rate/weight selection. Keep TS/JS mirrors and public exports aligned.
3. **Separate later gates.** Measure bounded repeated action, admission, success, defeat, save/reload and publication under an instrumented 5 MiB limit before combat implementation. The retained Soundings peak 5,076,206/5,242,880 UTF-16 bytes leaves 166,674 bytes. Only after capacity and the accepted admission/outcome/recovery contract are executable may a bounded combat caller package be installed and independently accepted. Static authoring and action-context reachability do not themselves accept combat.

The first executable prompt should own only slice 1, with one authored record, schema, content-lint cross-validation and focused positive/negative lint tests. Its checkpoint is a reviewed static-authority commit. Slice 2 is a separate owner/caller prompt because it changes campaign command and UI behavior and needs real creator-to-action proof. This split keeps the canonical authoring choice and later runtime admission distinct without assigning a new game version here.
