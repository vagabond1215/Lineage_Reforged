## Implemented checkpoint

`gear-instance-owner.ts` owns a version-1 native gear graph. Every gear record has a generated stable `itemInstanceId`, canonical item reference, individual durability, and exactly one worn, bag or overflow location. The graph validates unique IDs, one item per worn position, authored slot eligibility, bag slot capacity alongside fungible stacks, receipt uniqueness and condition bounds. Invalid source graphs, stale revisions and unsupported items fail without mutation. Accepted grants and moves advance one revision and retain a request ID so duplicate retries cannot mint or move another item. Equipping into an occupied slot moves the displaced instance to the vacated bag slot when available, otherwise to a free bag or overflow. `getWornGear` projects only physically worn instances. JSON readback rejects incompatible graph versions and malformed graphs.

Native position IDs include separate Equipment and Clothing body layers, Back, sided Ear/Eye and ten sided Ring positions. Only the six explicitly seeded records in `equipment_fit_profiles.json` have authored fit in this checkpoint: Composite Bow, Short Bow, Arming Sword, Pickaxe, Casual Tunic and Leather Light Armor. The new fit table is checked against canonical item identity by its regression test. It does not imply a handedness or multi-slot coverage rule, and unprofiled items cannot be granted into this owner yet.

## Exact activation boundary

The selected production path still constructs and mutates the 17-key `playerState.equipment` map, bag item-type stacks and `ui.character.item-stash.*` flags in `newGameSnapshot.ts` and `characterPanelState.ts`. Combat, resources, player-engine counts, Character rendering, SaveManager `lineage.save_snapshot.v2`, IndexedDB artifact validation and Ashen Reef survey capture still read that old representation. The new owner is **not imported by those production callers**, stored in a campaign, or deployed. Adding it as a parallel field now would create two mutation authorities and allow inconsistent saves.

The next cutover must be one reviewed coherent change: finish authored fit for every actually granted starter and supported gear item; put this graph into a new-format PlayerState and replace old gear stacks/equipment as mutation authority; derive effective worn projections for combat, resource, UI and survey consumers; route every grant/Equip/Unequip through the one owner; version the SaveSnapshot/envelope and current-format survey witness; reject obsolete development saves with new-campaign guidance; prove current-format Save/restart, interruption and stale publication. This is a source coupling boundary, not an old-save migration obligation. No old 17-slot conversion, stash recovery, reset, or quarantine is planned.
