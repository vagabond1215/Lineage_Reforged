## Fixed workload and measurement plan

Use newly created **disposable isolated local origins** and synthetic accounts only. Mount the actual default App. The fixed growth target is **120 accepted descendant saves** from ordinary selected creator/World play, split into six blocks of 20; alternate Slot 1 and Quick Save where the UI permits, retain a fork from a historical address, and use two simultaneous same-origin tabs for at least two blocks. At each block boundary perform a selected load and full-page restart in one context; at blocks 2, 4 and 6 do both. Include at least 24 selected loads and six restarts overall. Run genuine World actions and the reachable Soundings offer/four shifts/turn-in, Normal-Stakes defeat/recovery or terminal lineage transition as distinct selected branches; label any fixture-only branch as supporting rather than selected legitimate growth. If a mandatory branch is not reachable in the fixed workload, mark that row `UNREACHABLE`, not `PASS`. The acceptance threshold is a measured 120 accepted saves plus all required branch histories; no universal save-count or byte guarantee is inferred. Stop the run if the G10C 64 MiB archive cap is approached, a browser quota fault occurs, or an accepted graph fails validation; record the exact last good and attempted state.

At baseline and after every 20 accepted saves, record exact archive UTF-8 bytes, full digest, all 14 family row counts and serialized row bytes, head/revision and non-head identities, accepted account/Chronicle/witness/recovery counts, `navigator.storage.estimate()` usage/quota and `navigator.storage.persisted()` where available. Calculate per-block deltas and a transparent 1,000-save scale projection from observed growth, with no universal quota claim. Check actual G10C export size and selected download at baseline/final; capture only nonsecret counts/digests/IDs. Never preview, log, attach or commit verifier contents. Archive files contain sensitive sign-in and game-state material and must remain private.
