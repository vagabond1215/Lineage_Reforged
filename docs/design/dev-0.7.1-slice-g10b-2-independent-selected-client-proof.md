## Evidence and decision

The matrix was written during the first ordinary Soundings exploration, before the two-context and remaining probes; it was not fully prewritten before all probes as the active prompt required. This sequencing limits the independence claim and is an additional reason not to accept G10B.

### L1 / P1 / F1 — selected two-context owner

The new mounted default-App harness `apps/rpg-ui/g10b2-two-context-20261012.html` ran on fresh local origin `127.0.0.1:5288` with two simultaneous same-origin App iframes and a disposable account. **19 supporting assertions passed, but the L1 gate failed.** A selected first-campaign publication was interrupted only at mandatory consumer completion; owner readback showed `accepted_pending_consumers` and slot `pending_consumers`. B restarted and completed that exact publication. A Retry read the same ready address. The descendant case repeated this boundary; B's competing Save blocked without replacing the pending publication, then B Retry completed the exact descendant and A Retry read it without a new head.

A one-shot fault returned a blocked result only after `CleanEpochDescendantAdapter.save` had completed its real owner call. The accepted head was `artifact.e0d0e749-f45d-4b73-b573-0432f7c8d365` / `publication.4db902a9-41c2-4bb9-abe6-f991550a938f`, campaign head revision 3. B's stale Save blocked; A's selected Retry and a subsequent restart read exactly that head without a new publication. An unchanged explicit Save after restart produced `artifact.332be450-cd87-495b-91cc-63d1a9e2df3d` / `publication.3ab81869-6a32-4e57-8008-1a3af23c29cb`, revision 4. This second button press could be understood as a new user command, but the selected client retains no durable request identity with which to distinguish it from retry of the lost intent. Therefore exact same-intent replay is **not proven**; the harness reports L1 FAIL under the required no-second-head criterion. Pre-submit rejection and changed-intent controls are not asserted. Account revision contention was observed. On an earlier disposable origin, a selected reset completed and showed empty slots, but automatic approval review rejected the subsequent stale-context Save because it could recreate campaign data after reset. That action was not retried or bypassed, so lifecycle-generation fencing is unproven here.
