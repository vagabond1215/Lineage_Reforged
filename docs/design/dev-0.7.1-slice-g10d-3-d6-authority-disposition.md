- G10D.2 D3–D5 retain their independent fault and size-boundary scopes. Its **valid** 67,047,945-byte owner archive restored exact fourteen-family digests; that is D5 size evidence only, not D1/D2 capacity or eviction evidence.

The actual origin-wide usage/quota readings remain in `docs/dev/evidence/g10d2-fault-persistence-results-2026-10-17.md`. Denial means no granted persistence protection was shown; it does not establish eviction.
- D6-R1: the password-gated, user-held complete archive restored to fresh isolated origins after **safe origin-loss simulation**. Selected login, mixed-history/non-head load, restart, later legitimate fork Save, second backup and exact fourteen-family comparison passed. This proves the recovery path under the tested empty-origin condition. No site/user data was cleared.
- D6-E1: **no actual involuntary browser eviction was observed**. The mounted in-app browser has no safe deterministic eviction control. Disk-pressure attempts could affect unrelated user data; manual profile/site clearing would be a different event. Neither persistence denial nor the simulation is an eviction witness. No eviction-protection guarantee or automatic recovery of data without a user-held file is claimed.

The product contract after detectable loss is fail-closed: an unavailable database, corrupt record or retained session pointing to a missing account cannot become a successful reset/delete, default account, playable empty slot list or save notice. The accepted G9A/G10 caller authorities define this; current `cleanEpochAccountAdapter.ts` rejects a retained session whose account is missing, `cleanEpochLauncherRead.ts` rejects missing selected accounts/failed inventory, and `EpochApp.tsx` presents blocked Retry on bootstrap failure. Those source-path observations are read-only reconciliation, not a new browser loss test. If **all** origin state and the session hint disappear, a first visit is indistinguishable locally from an empty fresh origin; the user-held archive import is the recovery route. The selected G10D.2 fresh-origin restores directly prove that route, not diagnosis of an unobserved eviction.

The original G10D ledger's D6 contractual row is **PASS within this stated authority and selected restore scope**: D6-P1 measured, D6-R1 selected recovery proven, D6-E1 authority/environment resolved. This does not change D1/D2 or D3–D5, accept G10D overall, install G10E, authorize activation/deployment/site clearing, accept `DEV-0.7.1` or Game version, change `GAME_VERSION`, or integrate held branches.
