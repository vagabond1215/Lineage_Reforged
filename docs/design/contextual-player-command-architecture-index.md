## Route

**Current priority:** owner-directed combat skeleton coverage/ownership audit, then separately scoped mechanical combat/selected-action integration; natural encounter winnability and tuning wait for future creator/equipment/skill/item integration. Earlier selected victory/choice and durable continuity are preserved as *later representative/Game-version evidence requirements*, not the next skeleton implementation gate. A separate Game-version decision remains required for Game promotion and precedes the previously gated Home implementation. This contextual architecture may be accepted in parallel as documentation. The first Home/context implementation then uses existing production commands only and carries environmental provenance without inventing new verbs. The next environmental-affordance kernel must generalize across contrasting authored ecology such as steppe, forest, river/floodplain, estuary/tidal coast and upland/subterranean contexts before the first resource owner is broadened. Entity-specific presentation follows the clerk / board or desk / posting-card / receiving-clerk lifecycle without inventing nested commands. Immediate player actions and direct interactions use the contextual command model; business/property/personnel/crew/policy administration stays in management surfaces and may be linked from Home without becoming a world command. The structural UI overhaul consumes that same split. Separately accepted resource, transaction, employment/social, property and other sandbox owners follow. No new production capability, save schema, deployment or Game-version change is authorized by this package.
