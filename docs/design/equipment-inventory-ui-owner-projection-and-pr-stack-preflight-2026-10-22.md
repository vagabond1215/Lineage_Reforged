## 2. Live Character panel and action source map

They already use `buildEquipmentEntries`, `buildInventoryEntries`, `equipInventoryItem`, `unequipItem`, `consumeInventoryItem`, current selection and `panelNotice`. A first UI pass should **clarify** these two destinations, not introduce a second item management service.
- [`characterPanelState.ts` on PR #10](https://github.com/vagabond1215/Lineage_Reforged/blob/codex/equipment-slot-reequip-repair/apps/rpg-ui/src/features/characterPanelState.ts): `EquipmentEntry` includes `slotId`, readable `slotLabel`, item ref/title and detail; `InventoryEntry` includes item identity, quantity, bag/overflow location/container/index, category, `preferredSlotId`, `consumePreview` and detail. **A single preferred slot is a limited present resolver**, not a complete multi-slot compatibility or handedness system. Inventory `Equip` is currently disabled if `preferredSlotId` is absent; `Use` is currently disabled based on a heuristic `category !== 'consumable'` in PR #7. This is a potential UX mismatch with actual `consumableProfileId` ownership. Confirm exact authored profile before changing behavior; never enable generic use from name heuristics.
- [`equipmentSlotEligibility.ts` on PR #10](https://github.com/vagabond1215/Lineage_Reforged/blob/codex/equipment-slot-reequip-repair/apps/rpg-ui/src/game-shell/equipmentSlotEligibility.ts) is canonical-ID/key checked but recognizes **only supported subset**: authored weapon right hand, shield left hand, specific torso clothing and existing explicit starter mappings; no invented dual-wield/handedness/armor-coverage inference.

## 3. Smallest valuable presentation slice

**Deliver a first Equip/Inventory task experience that is real even without future item-instance systems.**

1. **Equipment:** readable functional slots, occupied vs empty with correct slot and item; a single inspectable selected slot, small truthful equipped details; clear owner-backed Unequip, and a route to **filtered Inventory** for actually supported replacement equipment. A direct contextual eligible-item picker may be implemented only if it calls current `equipInventoryItem` on a *fresh live entry*, revalidates every time, preserves notice/displacement/metadata and can demonstrably handle list-filter/selection changes; otherwise hold picker and keep route.
2. **Inventory:** carried bag/overflow quantity, name, category, filtered/sorted entries, selection and source-backed Inspect / Equip / Use availability. Avoid "Equipable" for a supported consumable or "Use" for an item lacking a real consumable profile. Provide a brief readable reason (unsupported slot / no authored consume action / changed stack / empty or selected item) when disabled; only use actual state/profile evidence, not invented combat restrictions. Existing notices remain visible and distinct for success, rejection and stale state.
3. **Preserve actions:** current `equipInventoryItem`, `unequipItem`, `consumeInventoryItem`, `toggleFavoriteItem`, their actual caller snapshots and existing item/quantity/slot identifiers. Keep the existing Character selection, search, sort/category, favorite, inspector, keyboard and horizontal secondary nav usable. No duplicate manager or presentation-side mutation.
4. **Visual and accessibility:** 320, 375, 768 and 1440 widths, keyboard and focus return, readable item/slot label and numerical counts, no permanent second nav rail, no overflow into the status meters/condition popup. Calm forest/charcoal/cream with quiet metallic accents as accepted. If the PR #9 mobile layout is absent on branch, use a composed test worktree for viewport proof rather than importing its unrelated CSS into UX.
5. **Acceptance:** controlled initial empty/occupied slots, Composite Bow + Short Bow after composing owner PR #10, crafted item/unsupported selection, stale stack, occupied displacement, bag/overflow, quantity conservation, consume preview/use and SaveSnapshot serialization. Browser proof in the *real combined shell* should be labeled controlled if no legitimate authenticated selected campaign. Full selected Equip→Unequip→Re-equip/Use/Save→restart is still required before merge acceptance.
