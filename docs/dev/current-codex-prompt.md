- **Future world-driven live updates:** if and when an authoritative World service/coordinator exists, each subscribed tab receives ordered, versioned World state or committed deltas and automatically refreshes its **read-only view** on accepted changes. A shared Vite HTTP server or same-origin IndexedDB does not by itself provide a live World authority/push channel. A local-only implementation may use notification/invalidation plus authoritative IndexedDB readback, but that is not a remote World server and must not be described as one.
- **Future paused concurrent edits:** World pause is authoritative per World, not per tab; freezing simulation time does not freeze World revision or grant unlimited action credits. Mutating actions require authoritative serialized commit and an expected World/campaign/Save head. A paused-world action is either deliberately disallowed by the clock/action contract or committed under the same concurrency and time-cost rules as unpaused actions, never duplicated. If Tab A's command commits first, Tab B must apply a new authoritative update and must not submit its older in-flight edit blindly. On a true stale/conflicting pending edit, reject without publication or lost progress and show **“World progress changed. Reload this tab to continue.”**; reloading rereads the accepted World/Save/head. No silent last-writer-wins, automatic command retry, duplicate clock tick or duplicate side-effect.

Two tabs cannot eat the same portion, and the same actor cannot begin a second incompatible meal until its authorized busy window ends. Do not hardcode a universal five-second gameplay cooldown: game time versus wall time, and actions during World pause, need an explicit clock/action policy. The full worked contract is in [World loading/design §10.1](../design/welcome-world-library-character-entry-and-loading-plan-2026-11-11.md).
