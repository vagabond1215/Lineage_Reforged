## Scope and behavior

- `WelcomeWorldPresentation.tsx` owns the existing gated shell and view transition. `WorldCreator.tsx`, `WorldLibrary.tsx` and `worldPresentationState.ts` provide the form, library and typed readback/intent contracts. The Library shows separate preview-unavailable, loading, empty, ready/capacity and verification/error states. Ready uses only owner-supplied identity, name, date, scenario and supported rules, with no Play or Open action. The authentic app passes no inventory or creation callback in A3a, so it shows unavailable and never renders a fabricated World or reports durable creation.
- Back returns to the Library from Creator or to Welcome from Library. Home is centered and returns to the signed-in Welcome, and the right-side Library action opens the form. Focus moves to the active heading. The account menu and compatibility exit remain in the existing shell.
- The Creator validates the trimmed name (1–80, no ASCII control characters), displays the fixed First World/default scenario and Chronicle/Individual/Mortal/normal-stakes policy, and requires explicit confirmation. Temperature, rainfall and canonical six-season choices remain visible as disabled future settings. Persistent, Living, alternative difficulty and Hardcore remain unavailable. The final action remains disabled without the real owner callback. A mounted callback accepts only normalized name and stable generated IDs. A pending ref serializes duplicate submits and retries reuse the same intent. The form reaches a highlighted Library card only after the callback returns the matching verified World ID and the owner-fed record agrees.
- EpochApp, account validation, feature gates, and the World owner are untouched. A3b still requires reviewed compiled loopback gate reconciliation and credential-backed owner admission, including the remembered-session limitation and avoiding additional Save inventory recovery.
