## First player-facing UI deliverable

**Navigation:** signed-in Welcome -> Chronicle -> Your Worlds (actual owner-backed inventory) -> Create World form -> atomic Create -> real committed World card in Your Worlds. Back button on left, Home/Main centered in subbar (no breadcrumbs), contextual header/account/logout; respect existing themed components and 320/375/768/1280/1440 layouts, keyboard and touch. No extra World Overview stop. Logout and account switch clear in-memory draft, selection and pending visual state. Keep Classic/New UI selector and default launcher behavior intact. Never swap an authenticated profile into a different account World.

**Library:** loading, none, present, capacity reached, blocked/error and explicitly corrupt/readback failure must be distinct. Display only actual World IDs/names from the owner, creation date/status and supported real settings (Chronicle/Individual/Mortal/default scenario). Initial capacity is ONE World/account as enforced by PR102, visibly labeled a **pilot capacity**, not permanent product quota. When full, show retained World and disabled Create New World with explanation. Do not fabricate sample Worlds, character counts, geography screenshots, Save slots or simulated world-time progress. A valid empty World with zero characters and zero Saves is a successful World creation. If loader remains heavy, loading indicator may truthfully state verifying World; do not invent fast metadata shortcuts that bypass receipt/source validation.

**Creator:**
- World name editable, trimmed, 1..80 characters, reject controls/whitespace-only and invalid fields before submit; duplicate display names are identity-independent but pilot only has one World.
- Authored blueprint: **First World**, read only. Global scenario **First World Chronicle Default v1**, read only. Chronicle and Individual selected; Persistent and Living visible but clearly unavailable.
- Difficulty: Mortal committed preset as the only currently backed option. Show Favored/Forsaken future choices honestly; don't silently commit Mortal if user chose anything else. Normal stakes/Heroic World and Hardcore OFF supported by existing pilot contract; Hardcore future/unavailable. Do not conflate Hardcore with difficulty.
- Climate: Temperature Cold/Normal/Hot; Rainfall Dry/Normal/Wet. Starting season: Scenario Default plus the six exact labels from packages/content/base/world/calendar.json (Deepfrost, Thaw, Waking, Swelter, Harvest, Withering). Keep controls visually in place. The only A2b-effective environment inputs are canonical defaults; a nondefault UI draft MUST NOT be silently saved as if it affects engine climate/calendar, or silently ignored at Create. Either disable unsupported choices with descriptive text or permit exploratory selections but show explicit non-submittable validation until the engine has versioned effective-setting support. Do NOT introduce an independent UI-only persisted climate override. Remove "review only" language from genuinely supported controls; explicitly label unsupported settings Coming Soon.
- Extensible section for later World settings; no false causal controls, no extra RNG/terrain/map authoring, no user-visible generation seed. Source fingerprints/algorithm, hidden seed, receipt and immutable defaults come from owner and never editable by UI.
- Review/confirmation clearly displays the exact effective settings to be committed and the one-World pilot capacity. On submit disable double clicks, preserve stable creation intent and proposed World ID for same-form retries; generate IDs with browser-approved existing helper/crypto.randomUUID, never from displayName or timestamp alone. Original account adapter must issue and validate authenticated session, then owner re-fences account/generation/revision within transaction; do not trust selected display profile or localStorage hint as write authority.

**After Create:** await owner committed status and readback/verification. Navigate to Library, render actual World card and optional non-intrusive "World created" notice only after verified success. Do not attempt World simulation loading, spawn, character creation, gameplay Save binding, advancing the World clock or replaying future mutations. If callback fails, preserve validated draft and show actionable retry/reload. If commit may have succeeded but acknowledgement was lost, requery authoritative inventory before offering new distinct intent; never create a second World or overwrite first. A returning sign-in can list the existing World; if persisted session has no credential-issued write authorization, require explicit password sign-in or a separately security-reviewed equivalent; do not weaken A2b WeakMap authorization.

**Minimal loading boundary:** allowed World Library read of authenticated account World/receipt and verified genesis readback, plus creation receipt readback. Do not build generic savegame loader, materialized-region loader, simulation tick/replay, World/character restore pipeline or new per-character Save version. No Open/Play button unless a separately accepted World-bound character entry actually exists. When owner-backed character library lands later, selected World goes there without intermediate Overview.
