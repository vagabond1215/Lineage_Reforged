## 2. Persistence direction (proposed technical structure under owner direction)

Three distinct authorities:
- Shared immutable authored content catalogue/database: versioned map/geography/coordinate assets, regions/localities, settlements, climate/ecology/habitat baseline, resource definitions, items, cultures, calendars, rules, scenarios and algorithms/content packs. Do not duplicate these definitions into every World or character Save. Current canonical source is repository data; a manifest-verified read-only content pack/cache may serve the existing browser engine. No new external DB service required merely to implement this slice.
- World instance: account-scoped identity, generation/creation intent, immutable source/scenario version and full manifest fingerprint, internal retained seed and generation/algorithm version, effective supported rules and configuration, clock, revision, authority for generated instance entities and durable World-level gameplay data. Key all mutable state by accountId + worldInstanceId (+ entity/domain key as needed). Shared source records are immutable; World A cannot mutate World B or source content. Use references to source IDs, sparse changes and versioned materialized records where safe, authoritative retained state/checkpoints for quantities/identities not safely derivable. Initial engine-generated economy projection may remain in v8 World row as bounded tick-zero snapshot; do not prematurely normalize or introduce a new storage migration solely for theoretical optimization. Measure actual projection/row/archive bytes. Distinguish authoritative dynamic balances and RNG state from recomputable views/indexes/summaries; avoid persisting copies of source definitions or two mutable authorities. Later domain stores/checkpoints and event-tail compaction require a separately reviewed versioned schema and complete archive/cleanup policy, not ad hoc v8 additions. Event history needed for player-visible history/causality, idempotency or audit remains retained even when replay checkpoints compact technical logs. Explicit tombstones distinguish removed entities from absent overrides. Versioned checkpoints anchor subsequent events, no unsafe loss of factual history.
- Character/campaign/Save: player-specific state (attributes, inventory, location, skills, quests, personal history), verified World association and World revision/head references. World-shared clock/economy/local environment, persistent NPC identities, shared property etc. belong to appropriate World owner; family/account entitlement owners remain separate as already defined. Do not duplicate mutable World authority for every character. Existing native-v3 snapshots and closed histories are NOT rewritten, reparented or stripped to achieve this design; define later compatibility/migration/branch semantics. Loading an older character Save must never silently rewind a common World or erase another character's changes. Establish explicit revision conflict/rewind/branch policy before enabling that path.

Deterministic generation: shared source + scenario + effective rule set + internal seed + versioned algorithms, stable entity/area identities, per-domain/substream seed derivation independent of traversal order where appropriate. Reconstruct only when exact pinned inputs and deterministic algorithm contract available; keep committed changes and irreducible state, avoid rerolls on reload, retain actual generated outcomes if recomputation not guaranteed. Missing pinned content fails closed with actionable recovery; preserve old content versions or verified portable source pack separately, explicit compatible migration only. Source content should not be copied per World Save; portable backup must include/identify all data necessary for exact restoration and validate source availability, optional deduplicated immutable pack once per archive if later needed. Hash alone not a substitute for recoverable bytes.

Materialize by supported scope/detail: initialize global identity/scenario/calendar + actual engine-backed Starfall economy and shared authored map references. Existing engine is bounded to three local settlement IDs and two external trade context IDs; do not claim global economy/population/NPC simulation. Other regions can be read from authored catalogue and initialized at appropriate simulation resolution as their actual owners are implemented. Later materialize local areas once under stable identity; persist changes/depletion/deaths/construction and scheduled events under owner. No procedural continent, speculative new geography, fake inventory or unsupported simulation. Keep unsupported climate, season and difficulty choices visibly unavailable for real submit until exact causal/runtime integration is accepted. Per prior user intent retain future hot/normal/cold, wet/normal/dry and canonical six seasons as separate versioned configuration axes; not cosmetic committed options. First pilot Chronicle / Individual, supported Mortal/Heroic/normal-stakes/non-Hardcore only with executable proven mapping; no Living/Persistent. Use canonical clock/scenario; no fake actual world time. Existing future design decision for multi-World and explicit quota remains.
