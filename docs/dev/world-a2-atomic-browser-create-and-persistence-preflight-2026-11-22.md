## 2. Data ownership and conservative tick-zero classification

Existing A1 measurements are UTF-8 JSON serialized payloads, not physical IndexedDB storage: projection 6,715,533 bytes, economy ledger 46,560, hierarchy snapshots 173,895, derived marketStates 6,131,114 (about 91.3% of projection), settlement simulationStates 363,903, source pack 22 shared JSONs 13,950,389, World row+receipt 6,721,107+422 in-memory; archived fixture growth 6,721,568. These figures are not a license to discard values.

- **Immutable and authoritative genesis (persist):** account/World/creation-intent identities, account lifecycle generation, committed receipt, source template/scenario IDs+versions, *full content and algorithm source set* fingerprint (not only SHA-256 of template), generator version, stable internally chosen seed and seed policy, accepted immutable World rules, canonical clock seed/start, World revision and authenticated createdAt. Include exact-source retry/identity/collision fencing. Source definitions themselves remain shared, immutable, version-pinned and available to read/recover; never copy canonical atlas/settlements/item catalogues into every World/character Save.
- **Current mutable World authority (retain at each accepted head):** World clock and revision, economy inventories/balances only if and when an owner truly commits them, production/resource depletion, persistent identity/area/scheduled action/outcome changes, population/building ownership/damage/real transactions, idempotent event/receipt history and pending consumer coordination. A history Save for an individual character must not rewind the shared World or replace another character's accepted mutation. No full rewrite of existing native-v3 history or silent v7->World association. Current A1 economic stockLevel is a pressure estimate; it is *not* minted actual player-tradable stock.
- **Candidate deterministic/ephemeral projections (recompute only when proven):** authoredPosture, warnings, aggregateEconomyHierarchy(snapshots), marketStates[].priceView and laborPressure and production estimate projections, and initial settlement simulation profiles, all when derived purely from exact source, clock, retained input authority and algorithm version. Concrete source: starfall-base-economy.ts invokes buildEconomyStateFromContent -> aggregateEconomyHierarchy -> buildSettlementMarketStates -> buildSettlementSimulationProfiles; runtime-economy.ts line 1210 derives marketStates, priceView from index/market snapshot; settlement-simulation.ts line 1997 derives initial profiles from settlement/market inputs. Type contracts in packages/shared/types/src/contracts.ts: SettlementMarketState has stock, laborPressure and priceView; priceView includes calculated buy/sell estimates and pressureSources, not a confirmed offer. EconomyLedgerSnapshot aggregates balances; CivilizationEconomyState includes nodes plus lastSnapshots/lastLevelTotals/marketStates. Do not assume every future version of these fields is recomputable: if actions commit prices, stocks or structures they become authoritative World-owned data.
- **Cache and display only:** price explanations, market value breakdowns, derived summaries and source indexes may be reconstructed after verifying exact inputs. runtime-economy.ts runtimeIndexesCache and settlement-simulation.ts simulationIndexesCache are currently module-scoped; isolate/cache-key or reset across distinct fingerprints/instances before reusing in the actual app. Avoid persisting duplicate render models as an additional source of truth.

**A2 decision boundary:** first measure both the historical complete projection and an explicit compact genesis candidate. For every omitted field, prove an executable rebuild function from pinned source + retained current-state inputs, with matching normalized digest after fresh browser realm restart; distinguish tick-zero rebuild from future mutated World reconstruction. Prefer a small durable row if proven, but do not break v8 schema/archive/receipt validation to save bytes without versioned migration. A 6.7MB bounded full genesis as an explicitly measured safety pilot is acceptable if exact replay/compact policy is unproven; do not quietly claim efficiency and do not turn a safety pilot into final storage layout. Actual physical IndexedDB bytes remain unmeasured. Avoid new object stores or format changes unless complete upgrade/archive/delete/reset/recovery evidence is provided.

## 3. A2 runtime path, pin versioning, and durable create

**Critical A1 preservation trap:** A1 source-pack.mjs hard-pins *current* registry producer Git blob cf58c82d4703b6fbc209e7701233881cdad415f3 and manifest 8dd06caec702c439ed36b59ac24c146b266adffb. A2 registry/contract changes necessarily invalidate the A1 current-working-tree pin. Do not silently change/rewrite the historical A1 result, bypass it, or copy whole source into parallel duplicates. Preserve exact A1 proof at immutable commit 3994cccf; run historical A1 in a separate pinned checkout/fixture if needed. Create a deliberate versioned A2 manifest and source-set identity for the successor. New fingerprints must bind actually executed algorithms, content, scenario, producer and transform version, not only an arbitrary asserted digest. Node and browser must build from identical accepted source bytes, with missing/mutated/unavailable pins failing closed. A1's original historical source ID remains meaningful for old Worlds.

Integrate a tested canonical content provider into the **actual browser World create path**, not merely isolated A1 HTML or a fake JSON response. It should preload validated content before invoking synchronous existing engine algorithms; keep exact manifest-version scope/caches and node-side API equivalence, isolate async preload from IndexedDB transaction to avoid transaction auto-close. No browser runtime dependency on node:fs, no new economy authority or unverified blobs. Creation builds a candidate out of transaction; commit only in existing cleanEpochAccountStore v8 account-fenced READWRITE transaction; validate session identity/revision/generation and complete source/rules/seed/scenario/intent once inside same transaction, create world+receipt atomically, read exact durable pair and verify full projection or compact rebuild. A same-intent retry *must return the original retained outcome* even across reload; a changed request with same intent or different intent over cap conflicts; stale owner/half-pair/source mismatch rejects, not empty list or a new roll. No success UI before readback.

Existing firstWorldDurableRegistry.ts asserts status CREATED_EMPTY, revision 0, clock zero, empty associations and one World/receipt pair. That is a valid genesis validator, **not** a future mutable World validator. Design separate immutable genesis/receipt validation and revisioned current-state validation for later L5/L9; do not require a changed World to still be revision zero. Existing v8 graph currently one World/account; either explicitly deliver a one-World **pilot** with enforced limit and honest UI, or version schema/graph+receipts for multi-World and prove two independent same-account Worlds and quota rejection before claiming a full World Library. Multi-World is product direction, not yet accepted in PR102.

World Create settings: First World blueprint, Chronicle/Individual, supported Mortal/Heroic/normal-stakes/non-Hardcore only until actual engine difficulty propagation proves alternatives. Seed retained privately and stable over retries; calendar canonical createInitialClock tick zero (Deepfrost day 1, year 1), no time advanced by menu. Temperature hot/normal/cold, rainfall wet/normal/dry, canonical starting six seasons/Scenario Default, and other rules remain intended future *effective* World-level options, not unverified active mutable sliders. If business demands different start season now, implement exact tested calendar/economy/season contract before enabling, not cosmetic saving. Persistent, Living and Hardcore remain held.
