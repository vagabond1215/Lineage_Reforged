## Finding and bounded repair

`InventoryEntry.id` includes item ID and stack index. Two same-item stacks can coexist in one bag; consuming the first removes index 0, and the second inherits the first row's ID. PR #11's ID-only `selectVisibleItem` then treats that second stack as the old actionable selection. The new regression failed before repair (`selectVisibleInventoryItem is not a function`), and the live entry IDs confirmed the collision. `CharacterPanel` now binds an explicit inventory selection to the current inventory object. A changed inventory state or hidden row has no actionable selection until the player chooses a current row. Favorites, pins, sorting and filtering retain their separate controls. The badge says `Supported equip slot`, which describes the actual resolver projection rather than promising a successful transfer; the action says `Use Item` because authored profiles also cover items outside the heuristic consumable category. No item identity, save schema or owner rule changed.
