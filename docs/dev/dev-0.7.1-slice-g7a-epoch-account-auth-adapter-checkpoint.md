## Scope and authority

`CleanEpochAccountAdapter` wraps the clean-epoch IndexedDB owner for explicit-ID registration, PBKDF2 sign-in, validated session-hint selection, revisioned profile update and password change. The caller creates an account ID before the async registration call, so a lost response can retry that exact identity; a simultaneous same-input registration converges on the retained winner after password verification. No old credential, account or campaign storage is read or copied. The only local-storage write is the epoch session hint, checked against a retained account on selection. A malformed or stale hint, unavailable store, invalid credential, failed hint write and stale account revision return typed blocked results. The picker exposes only display identity, not credentials.

Sign-in verifies the retained PBKDF2 verifier and rereads the account after the derivation await. It does not advance account revision merely to record a login timestamp, because that could strand a prepared first-campaign attempt after restart. Registration and account mutations still await exact IndexedDB readback. A failed hint write may leave a fully committed account; the blocked result preserves its account ID and a later password sign-in can recover access.
