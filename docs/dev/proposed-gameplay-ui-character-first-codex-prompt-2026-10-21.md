## Exact first implementation slice

**Primary goal: Character Overview and its local sibling navigation only.** Keep `InGameShell` global rail, current TopStatusBar game resources, six domains, Settings/save and all actual action routes working. Do **not** use this slice to refactor global `PanelLayout` used by unrelated domains. Avoid code changes to `WorldPanel`, combat owners, food intake, character creator, persistence types or unrelated panels.

- Replace Character's **second permanent vertical SidebarMenu** with **one responsive horizontal subsection strip** immediately below the global top band/at the top of Character's main area. For a first scoped implementation the strip may sit within Character until a later shell-wide secondary-nav contract is accepted; do not pretend all domains have been migrated. Retain Overview, Skills, Equipment, Inventory, Traits/Effects, Geographic Knowledge, Standing, Reputation, Discoveries; Attributes may be retired from primary nav **only if all detail/selection routes remain accessible**. Preserve selected section, keyboard tab/arrow conventions, visible focus, scroll-to-active, labeled overflow and responsive behavior. Do not create nested tabs.
- **Overview is identity/capability, not Home or a generic body-state dashboard.** Present authentic player identity (Ancestry, Origin/Background only when owner-backed), all nine attributes together, leading skills and meaningful Echo Level/Growth, a **compact** equipped-gear summary that navigates to Equipment, and optional earned distinctions. Do not invent placeholder equipment, buff descriptions, character titles, badges or stat values.
- Show `STR, DEX, AGI, CON, VIT, INT, WIS, SPT, CHA` from `CHARACTER_ATTRIBUTE_ORDER` and the *current* owner-backed attribute resolver as a dense, accessible 3×3 matrix on desktop and reflow at smaller widths. Each value/name is visible; description and source adjustments accessible via focus/click inspector or details. Do not show only STR/AGI/SPT as `Core Stats`, or repeat `Unmodified`/`Developing` tags on every cell.
- Remove the oversized permanent `ReadinessCard`, neutral condition/recovery recommendations, repeated HP/MP/Stamina rows, duplicated status chips, `Field Shortcuts` generic counters and `Runtime Bridge` developer readout from Character Overview's **default player presentation**. Keep meaningful medical/recovery information reachable in an appropriate existing owner-backed detail; do not discard authoritative state or useful accessibility warnings. Adapt summary slots to actual data, not fixed card count.
- Keep functional Equipment and Inventory destinations **separate**. Overview shows no more than a small selected set of meaningful equipped items, labeled by slot and linked to Equipment. Do not clone an item manager on Overview. Retain existing actual `equipInventoryItem`, `unequipItem`, `consumeInventoryItem`, slot legality, item identities/stack counts, favorite/pin, selection, sorting, filters, previews, notices and Save/readback. A slot-based eligible inventory picker is a **later** bounded item-UX owner consumer, not necessary in this slice.
- Preserve top-band HP/MP/ST data and existing effect/condition warnings. The bigger capsule-free HP/MP/ST bars and compact icon status bar are **the next shell presentation slice** after Character acceptance unless a small, testable shared style adjustment can be separately justified without scope growth. Never drop an urgent real alert in pursuit of visual minimalism.
- **Do not implement the signed energy bar or three available nutrient microbars**: `energyBalance`, `proteinSufficiency`, `dailyCarbsConsumed`, `dailyFatConsumed`, `energyReserve.quick/stored` are not the future nutrient reserves. Current truthful hydration/energy may remain accessible under their actual meanings. Retain no fake Hunger/Satiety meter.
