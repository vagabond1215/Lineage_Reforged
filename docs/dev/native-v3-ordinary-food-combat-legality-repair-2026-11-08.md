## Reproduction and repair

The retained source test SHA-256 `6B6B24D2A91EF015D7B16BA9B107B8ED40078C27E5FF2C2D73EC829DD0BBFFC7` was copied into `apps/rpg-ui/tests/native-food-combat-legality.test.mjs`. On the unmodified #70 source, both the direct selected item bridge and selected-session wrapper accepted a Traveler Ration during a real authored active encounter: quantity 1 became 0 and daily calories rose by 22 while combat stayed active. Its pending-defeat control passed.

`consumeNativeFungible` now refuses a new ordinary nutrition request when the canonical active encounter has state `active`. The check follows receipt replay, source revision/fingerprint, exact stack and authored nutrition-profile validation, and precedes all inventory, body, resource and receipt mutation. The selected Character reader disables that ordinary Use affordance with an owner-backed reason during active combat. It does not change gear admission or grant any combat item action. Later potions, medicines, antidotes and supplements require a separate combat action, timing, effect and expenditure owner.

## 2026-11-08 edge-case follow-up

The [connector review](https://github.com/vagabond1215/Lineage_Reforged/pull/72#issuecomment-6724911661) identified a pending-defeat availability mismatch and asked for the retained-encounter boundary to be checked. Follow-up code/test commit: `18ecc8ae828802f893b1aaebc9ce1c64675a66f0` on the same draft #72 branch.

- **Encounter lifecycle:** `createEncounterFromSpawnCandidate` creates `state: "active"`; the supported pause path reports a `paused` delta while the encounter remains `state: "active"` with `paused: true`; the normal resolution tick clears `activeEncounter` after recording its outcome. Nearby encounter admission and travel already treat any non-null `activeEncounter` as occupied. Ordinary nutrition Use and its Inventory projection now use that same retained-encounter boundary. This includes any future retained transitional state without granting a combat item action. No ordinary owner path producing a persisted literal `forming`, literal `paused`, or non-null `resolved` encounter was found, so this is defensive consistency rather than a claimed newly reproduced bypass.
- **Paused check:** a real authored encounter was created first. A test-only supported pause representation (`pauseAllowed`, `paused`) was recognized by `tickCombatFoundation` as a `paused` delta, validated as a native snapshot and admitted through the campaign session before the selected Use check. This proves the engine-recognized pause state remains blocked; it does not claim a production UI pause command was exercised.
- **Pending defeat:** a valid selected pending-defeat snapshot previously projected its authored Traveler Ration with `canUse: true` despite direct campaign admission rejecting `recovery_pending`. The added assertion failed **2/3** before the UI repair (`true !== false`), then passed. `readNativeSelectedCharacter` now uses the existing `hasPendingNormalDefeat` owner receipt: eligible nutrition shows `canUse: false` and a recovery reason, including in rendered Inventory. Unsupported Arrow Bundle still says `No authored consumable effect.`; normal playable noncombat Use stays available. Execution admission was not duplicated in presentation.
- **Ordering and adjacent boundaries:** accepted noncombat request replay after combat remains `duplicate`; a conflicting request ID remains `invalid`; stale stack/session requests remain `stale` or rejected. Selected direct pending-defeat admission remains `rejected` with unchanged snapshot/control. Existing gear and v2 item callers were not changed.

Free-form active-effect labels and authored ability target conditions do not establish an out-of-combat voluntary-action owner. No independent unprotected state was reproduced; external care and any later incapacity action gate need separate authority.
