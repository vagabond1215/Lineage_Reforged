## Repair boundary

`inventoryPresentationId` is an ephemeral JSON tuple of live entry location, container index, stack index, item ID/key and unchanged entry ID. `inventorySelectionFor` is the click-path constructor. The same key selects the visible entry, supplies the React row key and drives one row's selected styling. Equip and Use still receive the exact `InventoryEntry` returned by `buildInventoryEntries`; no entry ID, canonical stack, SaveSnapshot field or owner contract changes. Inventory-object-reference invalidation remains in place. Filtered-out rows have no action target; sorting and item-type favorites retain the selected row; immutable quantity, bag-order and SaveSnapshot reload changes require reselection.

Bag ordinal is shown beside the existing bag label and in the Inspect button's accessible name, so otherwise identical rows can be distinguished without claiming durable bag identity. The shell persists `pinnedRecordIds` using old `entry.id`, which collides for these rows. Pin controls on rows with colliding IDs are disabled with an explicit reason. Existing unique-row pin keys and item-type favorite semantics remain intact. Per-row durable pinning would require a separate shell/persistence decision; this repair does not invent one.
