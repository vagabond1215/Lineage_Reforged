## Durable pilot and source authority

- Browser create/reopen is restricted to the normal compiled app in **world-owner-review** mode on loopback. The caller uses credential-verified sessions issued by the actual account adapter in the same realm. A copied session object or one issued for another account owner fails. The ordinary build and native staging keep the review path off. No default World navigation or controls were added.
- The [v3 manifest](../design/first-world-economy-source-manifest-v3.json) composes all 50 original/v2 pins with five exact successor verifier, build, account, registry and durable-pilot pins. Build verification uses original bytes and the unchanged A2a Worker. The new durable fingerprint is `sha256:90d19ed5fa6f9c06bc093d6f775b65a5b69ad12b66a40362bd42a3bf948cfe33`. The retained binding also records the exact v2 economy source, scenario ID/version, serializer, World clock, genesis-only revision and fixed Chronicle/Individual/Mortal/normal-stakes/non-Hardcore pilot rules. A domain-separated SHA-256 seed is bound to account generation, intent, World identity, source and rules. Existing tick-zero algorithms are deterministic and do not consume randomized variation. The retained seed is reserved for future versioned generation and is absent from any player UI.
- The existing v8 stores and v2 archive envelope retain their key paths and family count. Only the World and creation receipt families accept matched version-2 compact pairs alongside original full version-1 pairs. The older v8 validator rejects the newer row version. No in-place migration of old World records or Save association was added. Archive export and restore verify exact source reconstruction outside transactions; original v7 archives retain their first 14 families without invented World associations. The same compact proof runs before reset/delete and the transaction rechecks the exact pair.
- Creation awaits and validates the verified Worker before entering the indexed transaction. Inside, it fences the original account ID, revision/generation, lifecycle, account quota and exact pair/source binding. It inserts World and receipt atomically. A race-matched retry returns the original retained timestamp, seed, projection, and pair. A retry whose originally observed World disappeared cannot write a replacement. One readonly transaction reads the World and receipt after commit. Reopen reconstructs tick zero in a new Worker, then rechecks authentication and exact retained readback. This validator admits only genesis, not an evolved World.
