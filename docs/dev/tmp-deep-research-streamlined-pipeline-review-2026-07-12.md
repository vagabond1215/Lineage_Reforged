## Accepted Streamlined Pipeline

The current long sequence remains available as a tool, but it should no longer be mandatory for every lane. Use this default pipeline:

1. **Milestone and consumer selection**: name the player/runtime/validation consumer and the repository capability to be gained.
2. **Evidence and owner check**: reuse existing decisions; audit only missing evidence that can change the route.
3. **Readiness decision**: define dependencies, risks, validation, and stop conditions. Combine with evidence/owner work when scope is small and evidence is already strong.
4. **Minimal implementation package**: schema/content/helper/runtime/UI/persistence changes may be combined when they share one consumer and remain reviewable. Preserve distinct owners inside the package.
5. **Consumer integration**: mandatory before declaring new static authority mature unless the authority is an explicitly approved foundational prerequisite with a scheduled consumer.
6. **Focused validation and acceptance**: run owner-specific green gates; treat known-failing audits only as baseline comparisons when relevant.
7. **Stabilization/support**: use a suffix for narrow repair, retry, post-implementation audit, or coordination alignment. Promote to a primary route only if the result changes milestone order, ownership, or maturity.
8. **Close, pause, or expand**: a zero-result closes/pauses the lane with one concrete reopening trigger. Do not rescan unchanged sources.

Stages may be combined when the change has one owner set, one consumer, low reversibility risk, and focused validation. Keep stages separate for high-risk persistence/account mutation, runtime commands/events, combat math, magic execution, economy mutation, broad content authorship, or any decision requiring user canon.
