## Owner and boundary

`apps/rpg-ui/src/game-shell/campaignIndexedDbStore.ts` adds a browser-native, asynchronous IndexedDB owner at schema version 1. Four account-scoped families have explicit record versions and queryable identities: immutable artifacts `[accountId, artifactId]`, campaign controls `[accountId, campaignId]`, slot addresses `[accountId, slotId]`, and Soundings witnesses `[accountId, campaignId, requestId]`. Each has an account/campaign index. Further account, attempt, recovery and migration families require later schema versions; this slice neither creates a second writable authority nor activates a migration marker.

The sole write operation receives the existing v7 envelope bytes, v1 control, exact expected predecessor and optional applied witness. It reuses the current save envelope/control guards and target-snapshot and Soundings provenance validators. It does not mint IDs or recalculate authority. Inside one read-write transaction it validates stored predecessor, immutable collision, current slot and retained witness, then writes artifact, control, slot and required first witness. Descendants verify the independently retained applied witness and first artifact. Commit or abort covers all four families. A separate exact readback checks the committed head, envelope and slot bytes, and witness. Same-source retry is idempotent; conflicting retries, unknown/malformed versions, stale heads, cross-identity data and missing/pending provenance fail closed. Unavailable IndexedDB, blocked upgrade, transaction abort and quota receive explicit codes.

`saveManager.ts` only exports existing v7/v1 types and guards for reuse. No production caller imports the new owner. Existing `localStorage` keys, saves, account profiles, attempts, launchers and ordinary App flows are untouched. Pure engines remain browser API free. There is no dependency, content, shared schema, `GAME_VERSION`, combat or economy change.
