## Four concrete A3 integration boundaries

**G1 / BLOCKER: DEV UI vs compiled owner mutually exclusive.** The UI function `isWorldPresentationEnabled(import.meta.env.DEV, welcomeEnabled, hostname, search)` requires DEV and `accountPresentation=1&worldPresentation=1`. `EpochApp.tsx` also defines `welcomeEnabled` through `import.meta.env.DEV` plus native DEV entry and `welcomeL1=1`. Meanwhile real `CleanEpochAccountStore.validateWorldAuthorization` requires `__LINEAGE_WORLD_OWNER_REVIEW_BUILD__` (only true for `vite build --mode world-owner-review`) and localhost/127.0.0.1. A production compiled review build has `import.meta.env.DEV=false`, so the current UI will never render World presentation there; conversely the ordinary Vite DEV UI cannot commit. **One exact compiled loopback-only opt-in must authorize both the real UI and its real World owner in A3b.** Do not flip an unrestricted flag, remove owner authorization, enable hosted/prod/default/native staging, or create a second reviewer-only World owner. Preserve Classic/New selector and default launcher.

**G2 / BLOCKER: restored session is not credential-issued World capability.** A2b account adapter stores a WeakMap only when register/signIn issues an explicit in-realm session; `selectSession()` returns `runtimeSession(hint,true)` directly, so remembered-session re-entry lacks the A2b World-write capability even though ordinary `validateSession` passes. Existing account reset also returns a generic runtimeSession. Minimal safe policy: signed-in returnees may list their World after owner-validated account identity, but to create or perform other World writes must reauthenticate with password through original adapter or separately demonstrate equivalent secure credential-verified issuance. Do not attach guessed capability to restored `localStorage` hint, do not copy session object, and do not rely on UI account displayName/route for write authorization. Unit/Chromium test cold remembered session + fresh explicit sign-in + cross-account and invalidated generation. The same account owner instance must be supplied to adapter and World writer.

**G3 / COUPLING: current World-entry path drives campaign Save recovery.** `EpochApp.tsx` `continueToWorlds` invokes `inventory(services, accountId)` before dispatching `OPEN_WORLD_LIBRARY_GATE`. That helper calls `recoverPendingInventory`, which may resume pending first/descendant publications and terminal addresses and reread all Save slots. `initialize` similarly boots signed-in accounts through launcher inventory and recovery. **This is not a World Library loader** and is beyond the owner's requested World creation scope. For bounded A3b, preserve legacy launcher recovery as-is, and avoid adding more dependence on Save slot completeness to render a World Library or issue Create. Design the smallest separately guarded World-specific authenticated route where practical, with a focused regression test that a World with zero characters/Saves is creatable and listable without World→Save mutation; do not undertake speculative full Save/boot rewrite. If existing launcher boot limits reachability, disclose/hold rather than bypass Save integrity or misrepresent an accepted global bootstrap.

**G4 / UI TRUTH + CONTRACT: presentation parameters differ from committed owner.** The current `WelcomeWorldPresentation` has review-only editable name, temperature, rainfall, season and a disabled Create; its centered subbar action is Create World, not requested Home/Main. The A2b actual `WorldPilotCreateInput` has only `expectedAccountRevision, creationIntentId, proposedWorldInstanceId, displayName`; pilot rules persist Chronicle/Individual, Mortal+normal stakes, Hardcore off, default scenario and zero clock, hidden SHA seed/source binding. `world.rules.difficultyPreset` remains null in older root shape, but accepted Mortal identity is in immutable `world.binding.rules.difficulty`; UI must read actual binding, not fabricate a preset from the root null. No effective climate adjustment or alternative starting season exists in A2b. Show Cold/Normal/Hot, Dry/Normal/Wet, Scenario Default + canonical six season controls in the form as future settings, but prevent committing unsupported nondefault values: disable them with Coming Soon explanation OR block submission and explicitly disclose they have no runtime effect. Do not silently ignore them or store an extra UI-only climate/season preference. Use a real validated name (trim, length 1–80, no controls), actual immutable World ID/receipt, scenario source and one-World pilot capacity. A successful empty World has zero characters/Saves; no fake World or character sample, title, map or time. Back to Library left, functional Home/Main centered, action/new World at right on Library; no breadcrumbs and no intermediate World Overview. Actual Creator submit uses form confirmation, no double requests or false success.

## Exact owner API and minimal integration contract

Owner `CleanEpochAccountStore` (PR102) offers `listChronicleWorlds(accountId)`, `createChronicleWorld(WorldPilotCreateInput, {adapter,session})`, `reopenChronicleWorld({adapter,session})`; account adapter offers `validateWorldSession`. Source Worker candidate generation is completed before IndexedDB readwrite transaction; paired World and receipt validated, genesis projection checked on reopen/World list, duplicate intent preserved, cap one World/account. The compiled `world-owner-review` fixture currently invokes these through `worldOwnerReview.ts` and a global `window.worldOwnerReview` exposed in `main.tsx`. **Production-facing Creator must not call this QA global**. It must use the actual `EpochApp` authenticated services/owner through typed narrow UI callbacks; preserve the original capability gate. Distinguish `loading | empty | ready | cap-reached | blocked | readback-failed` (as applicable), and identify malformed graph/source missing as failure, never empty. Do not emit success until exact durable pair readback; stable internal intent and World ID across retry, no reroll after lost ack. One actual World card should appear and remain on relogin; no Open/Play until real World-bound Character Library is accepted.

Only **World account inventory + Genesis reconstruction + Creation receipt readback** are authorized loading. Avoid new generic World loader, regional economy execution past tick zero, dynamic World mutation, local-area materialization, native-v3 Save migration, game clock tick/replay or World selection into gameplay. A3a can implement accessible typed UI without live owner on UI topic; A3b can reconcile with PR102 on a separately reviewed integration branch, using exact source baseline and versioned manifest successor when pinned files are changed. The previous UI Family Library package remains queued behind World Creator per owner direction.
